# XSS 跨站脚本攻击防护速查表

## 介绍

这是一个帮助开发者防御 XSS 漏洞的速查表

跨站脚本（XSS）是一个名不副实的说法。最初这个术语是源自一些早期的攻击方式，这些攻击最初集中在跨站窃取数据。从那时起，这个术语已经扩展到包括基本上任何内容的注入。XSS 攻击是严重的，可以导致账号冒充，观察用户行为，加载外部内容，窃取敏感数据等更多不良后果。

**这个速查表包含了一些预防或者限制 XSS 的技术。因为没有单门一个技术可以解决 XSS，所以使用正确的防御技术组合来阻止 XSS 是必要的。**

## 框架安全

幸运的是，使用现代 Web 框架的应用已经很少有 XSS 问题了，因为这些框架引导开发者们遵循良好的安全实践，并且通过使用模板化、自动转义等方式来减轻 XSS 攻击。然而，开发者们需要知道如果不安全的地使用框架 XSS 问题仍然会发生，比如：

- 框架用来直接操作 DOM 的逃生通道
- React 的`dangerousSetInnerHTML`没有净化（转义） HTML
- React 不能处理未序列化验证的`javascript:`或者`data:`URLs
- Angular 的`bypassSecurityTrustAs*`函数
- Lit 的`unsafeHTML`函数
- Ploymer 的`inner-h-t-m-l`属性和`htmlLiteral`函数
- 模板注入
- 框架过时的插件或者组件
- 等等

当你使用一个现代 Web 框架的时候，你需要知道你的框架是如何防止 XSS 攻击的并且知道它有哪些漏洞。有时你需要做一些超出框架提供保护的事情，这意味着输出编码和 HTML 净化可能非常关键。OWASP 将会为 React，Vue 和 Angular 提供框架所特有的速查表。

## XSS 防御哲学

为了使一个 XSS 攻击成功，一个攻击者必须能够在网页插入并且执行恶意内容。因此 Web 应用中的所有变量需要被保护起来。确保**所有变量**都经过验证并且经过转义或者清理，这就是所谓地**完美注入抵抗**。任何未能经过这个过程处理的变量都是一个潜在弱点。Web 框架使得确保变量正确验证和转义或者清理变得容易。

然而，没有完美的框架，安全漏洞在像 React 和 Angular 这样流行地框架中仍然存在。输出编码和 HTML 清理有助于解决这些漏洞。

## 输出编码

当你需要安全地显示和用户输入一样地内容地时候，建议使用输出编码。变量不应该被解释为代码，应该被视为文本。本节包含了每种形式的输出编码，使用场景，以及何时根本不应使用动态变量。

首先，当你希望以用户输入一样内容的时的方式显示数据时，应从你的框架的默认输出编码保护开始。自动编码和转义功能已被集成在大多数框架中。

如果逆没有使用框架或者需要覆盖框架中的空白，这时你应该使用输出编码库。每个用户界面中被使用的变量都应该经过输出编码函数处理。附录中包含了一些输出编码库的列表。

存在多种不同的输出编码方式，因为浏览器解析 HTML，JS，URLs，和 CSS 方式不同。使用错误的编码方式可能会引入弱点或者有损你应用程序的功能。

### “HTML 上下文”的输出编码

“HTML 上下文”指的是在两个基本 HTML 标签（像`<div>`或者`b`）之间插入一个变量，例如：

```html
<div>$varUnsafe</div>
```

攻击者可以改变被渲染为`$varUnsafe`的变量，这可能会导致一个攻击被加入到网页中去。例如：

```html
<div>
  <script>
    alert`1`;
  </script>
</div>
// Example Attack
```

为了安全将变量添加到 HTML 上下文并用于网页模板，请为该变量使用 HTML 实体编码。

如果你正在使用 JavaScript 来像 HTML 写入内容，请查看`.textContent`属性。这是一个**安全接收点**，会自动进行 HTML 实体编码。

```txt
&    &amp;
<    &lt;
>    &gt;

'    &#x27;
```

### “HTML 属性上下文”的输出编码

“HTML 属性上下文”是指变量被放在一个 HTML 属性值中的情况。你可能想这样做来改变超链接，隐藏元素，为图片添加代替文本，或者改变内联 CSS 样式。你应该对大部分放置到 HTML 属性中的变量应用 HTML 属性编码。在**安全接收点**部分提供了一些安全的 HTML 属性列表。

```text
<div attr="$varUnsafe">
<div attr=”*x” onblur=”alert(1)*”> // Example Attack
```

使用引号标记`"`或者`'`来包裹你的变量非常重要。引号使得改变变量操作的上下文变得困难，这有助于防止 XSS 攻击。引号也可以大福减少你需要编码的字符集，使你的应用程序更加可靠，编码更容易实现。

如果你使用 JavaScript 来向 HTML 属性写入内容，请查看`.setAttribute`和`[attribute]`方法，因为他们会自动为 HTML 属性编码。只要属性名是硬编码且无害的，比如`id`或者`class`，他们就是安全接收点。一般，接受 JavaScript 的属性，例如`onClick`，使用不被信任的属性值时是不安全的。
